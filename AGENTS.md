# Palace — agent notes

Palace is a packaged WinUI 3 / Windows App SDK digital asset manager (images, GIF, video; later more formats). The metaphor is a mind palace: **Library** (catalog), **Room** (moodboard / mindmap). Files stay on disk. SQLite + FTS5 is the index.

Keep this file current. When you change a convention (scan, thumbs, UI thread, cloud, packaging, tests), update the matching section here in the same change.

## Stack (locked)

- Packaged `winui-mvvm` only. CommunityToolkit.Mvvm, `{x:Bind}` with explicit `Mode`, `AutomationProperties.AutomationId` on interactive controls, `ThemeResource` (not hardcoded brushes).
- Never run the unpackaged `.exe`. Never set `WindowsPackageType=None`.
- Run: `.\BuildAndRun.ps1 . --arch x64` (or `winapp run . --arch x64`; the script forwards to the winui-dev-workflow skill script when present, else runs `winapp run`). Invoke attached runs asynchronously; the command stays attached while the app is open.
- Official skills: `C:\Users\iadag\.cursor\skills\winui-*` — load `winui-dev-workflow`, `winui-design`, `winui-packaging`, `winui-code-review`, `winui-ui-testing` as needed.
- Domain-reload-disabled is a Unity habit. It does not apply here.
- `Palace.Tests` is a separate `net10.0` project (`Palace.csproj` excludes `Palace.Tests\**`). Keep tests off WinUI / WinRT. Do not reference `FluentIcons.WinUI` from tests.
- Debug vs Release of the **same source** share one version number. Debug is not an older tree — it is untrimmed. Release is trimmed and currently crashes on `ItemsSource` COM wrappers; daily run is Debug (`.\BuildAndRun.ps1 . --arch x64`).

## Icons

Chrome icons come from `FluentIcons.WinUI` (`xmlns:ic="using:FluentIcons.WinUI"`). Use named `FluentIcon` / `FluentIconSource` values. Do not add Segoe hex `FontIcon` glyphs and do not add a second pack (Lucide, Tabler, Heroicons, Fluent Emoji).

- Command buttons stay **icon + existing text**. Do not convert toolbars to icon-only. Skip repeated “Remove” chip buttons.
- Room identity icons are a curated string id on `Collection.Icon` / `Room.Icon`, normalized by `Helpers/RoomIcons.cs` (default `BuildingBank`). Parse to the Fluent enum only in `Helpers/FluentGlyph.cs` — ViewModels stay pack-free.
- Gallery for names: https://davidxuang.github.io/FluentIcons/ — if an enum is missing, pick the closest Regular sibling.
- Keep existing `AutomationProperties.AutomationId` values; new pickers get stable ids (e.g. `GrdRoomIcons`, `CmbMosaicSort` / `CmbTagMosaicSort`). Tag chips use `TagChipItem.AutomationId` (`BtnTagChip_` / `BtnTagFilter_` / `BtnAssignChip_`). Board and assign groups use `TagBoardGroup.AutomationId` (`BtnTagGroup_`). Library mosaic folder headers use `TxtFolderGroup_` (`AssetItem.FolderGroupAutomationId`). Cloud source badges on Library / Tags tiles use `IcnCloudBadge_` (`AssetItem.CloudBadgeAutomationId`) — Fluent `Cloud` Regular, `ThemeResource`, on **every** Dropbox / OneDrive / API / hydrated cloud tile (`ShowCloudBadge`, including a decoded JPEG). Stamp `IsCloudBacked` from the source folder (`SourceKind` / `CloudFile.IsCloudBackedFolder`) plus `CloudFile.IsCloudBacked` on the file — not only `IsOnlineOnly`. Recycled `ItemsView` tiles keep `{x:Bind … Mode=OneWay}`. Kind badges (`IcnVideoBadge_` / `IcnGifBadge_` / `IcnHdrBadge_`) are small Fluent Regular glyphs (video, GIF, HDR) with `ThemeResource`; skip folder headers. HDR uses catalog `Asset.IsHdr` / Radiance path — never Open/recall the original to decide. Keep `ShowCloudTile` for online-only without a JPEG.

## Product rules

- Tags are **global**. Library sources and Rooms are **per project**. Default project name: **Palace**.
- The same disk folder cannot belong to two projects (`SourceFolder.Path` is UNIQUE).
- Delete = Recycle Bin + catalog row (`DeleteAssetsAsync`).
- Organize is on-disk, dry-run first, ask destination each run. Auto-organize is opt-in per source.
- Tag organize asks which parent chain. Assigning a tag applies configured implicits (transitive, cycle-safe).
- Tags page is an Eagle-style board. **All / Uncategorized / Starred are pinned at the top of the left group column** (in that order), then user groups (`TagPanelBuilder.BuildBoard`). Selecting a group stays in that column; child / sub-tags of the selected group are a **wrapping color-dot chip mosaic** in the next column (`RepTagChildren` `WrapLayout` under A–Z headers, `TxtTagChildrenHeader`) — not a tall full-width list. Creating or selecting a tag opens the group that contains it (`TagBoardExpand`). Uncategorized display name stays **Uncategorized**; automation id stays `BtnTagGroup_Ungrouped` (`IsUngrouped` / `AutomationIdOverride`) so the Library assign flyout does not become `BtnTagGroup_Uncategorized`. Search All chips have no `ParentId`. Tags inside a group are **A–Z with letter headers** (`TagAlphaIndex`). The Tags mosaic groups by **selected tag / next child / next child** (`TagMosaicGroups`; Priority then name). Keep `GrdTagAssets` and `TxtTagMosaicGroup_*` headers. **Select mode** on the Tags mosaic uses `TglTagSelectMode` / `TxtTagSelectionCount` (`TagsViewModel.IsSelectMode`, same `SelectMode.Summary` / checkmarks); range drag is `RangeSelect` (press then drag, touch press-and-hold then drag). Bulk actions stay off (Open only, `MnuTagOpen`). Grouped mosaic tiles are tab-stop; Enter opens the focused or clicked tile, not the first asset. Keep `SelTagScope` on the board scroller, `SelTagScopeAll` / `SelTagScopeStarred` / `BtnTagGroup_Ungrouped` on those rows, and `RepTagBoard`. Disk organize stays in the details column. Comma/newline batch-create uses `TagNameList`. Library tag browse toggles multiple tags with Any / All / None (`TagFilter`). Preview tags are wrap chips with × (keep `LstTags` / `BtnRemoveTag_*`); Manual/Implied are not face labels — Implied chips use muted opacity (`AssignedTagChrome.Opacity` / `ChromeOpacity`), source (+ optional k/n) lives in tooltip / `ChipAutomationName`; multi-select partial chips still show k/n on the face. `BtnBrowseTags` is the + Add tag flyout. Chip context: Filter in Library (`ApplySingleTagFilter` + `NavLibrary`), star, rename (focus `TxtRenameTag`), Add/Move to group (root groups via `TagGroups`), remove from this group, delete. Keep `MnuFilterTag` / `MnuRenameTag` / `MnuAddToGroup_*` / `MnuMoveToGroup_*`. Library `SelBrowseMode` / `SelTagMatch` follow `IsTagBrowse` / `TagFilterMode` on construct and Loaded — do not write the Folders/All defaults back. `SelectNode` stamps `SelectedName` and a rename baseline for every path (chip, group, create). `LoadSelectionAsync` applies the catalog name only when the tag changed or the box still matches that baseline — a cleared or edited box on the same tag is kept (`TagSelection.ShouldApplyLoadedName`).
- Library mosaic: viewing a **top-level** (source) folder groups tiles by the first 1–2 child folders. Header text is `Selected / Sub / Sub` (`FolderGroups`) as a **compact caption** (Fluent `Folder` + caption row, `TxtFolderGroup_`). `GalleryMedia.MosaicAspect` / `FolderHeaderAspect` (32:1) keeps each header on its own line — `LinedFlowLayout` has no break-before, so a narrower slot lets a header land mid-row after the previous group's leftover tiles. Nested folder browse, search, tag browse, and the all-library view stay a flat mosaic. **Sort:** `CmbMosaicSort` (Library) and `CmbTagMosaicSort` (Tags) share per-project LocalSettings (`MosaicSort_{projectId}` via `MosaicSortOrder`). Default is **Date (newest)** (`COALESCE(DateModified, DateAdded)`); also Name, Size, Rating, Type. `MosaicSortIndex` ignores ComboBox `-1` (`ShouldApplyIndex`) so init/unload cannot persist DateNewest over a saved key. Combos are **OneWay** + SelectionChanged after `Loaded` stamps the stored index (`_mosaicSortArmed`); TwoWay `SelectedIndex` also writes `0` (first item) when ItemsSource attaches. Library `Loaded` calls `ReloadMosaicSortAsync` so a Tags sort is applied on return. Sort runs in the catalog `ORDER BY` (`GetAssetsAsync` / prefix / tag filter / FTS) — do not load the whole library to sort in process. Folder headers stay non-assets and keep group-title order; tiles inside a group keep SQL order. **Row height** (`SldRowHeight`, icon + text) lives on the Library **status/bottom bar** with `TxtStatus`, not the search row. **Select mode:** the top-left `TglSelectMode` ToggleButton (Fluent `Multiselect` + "Select", above the breadcrumb in the mosaic column; `LibraryViewModel.IsSelectMode`) switches `GrdAssets` from `Extended` (Ctrl/Shift) to `Multiple` so a plain click or tap toggles tiles — `ItemContainer` draws the checkmark. Space opens overlay instead of toggling. In Select mode, pointer-down on a tile then drag selects the **contiguous mosaic range** from that first item through the last highlighted item (`RangeSelect` / `ApplyMosaicRange`; skip folder headers — not a marquee). Touch: **press-and-hold, then drag**. Overlay pan is not stolen (`AllowsGesture` is false while the overlay is open; mosaic `IsHitTestVisible` stays off). `TxtSelectionCount` shows `N selected` (or a hint when on and empty; `SelectMode.Summary`, refreshed from `RefreshSelectionSummary`). When select mode is on **and** tiles are selected, Library chrome shows **Tag selected…** (`BtnTagSelected`, Fluent `Tag` + text, Accent) which opens the existing assign flyout (`FlyAssignTags` / `BtnBrowseTags`). Hide the CTA when mode is off or the selection is empty (`SelectMode.ShowBatchTagCta` / `ShowTagSelectedCta`). Toggling off keeps the selection. Open / Move / Copy / Delete / Add to room / tag assign use the same `_selection`. Headers are not assets — skip them for selection, gallery, thumbs, and organize. Navigate only on header tap (or Open on a header); do not navigate from mosaic selection, arrow keys, or right-click. Asset context flyout stays on the tab-stop `ItemContainer` so Menu / `ContextRequested` opens Open / Delete / Move / Copy; headers cancel `ContextRequested` (`ShouldShowAssetContextFlyout`) so those commands stay off headers.
- Library-first until the matching 0.x slice. Do not invent Rooms canvas, gamedev formats, or AI auto-tag unless that minor is the work (see Version). Cloud is a **bonus**, not a numbered main slice and not the next increment after Library.

## Errors — log and Notify, do not crash

Unhandled and command failures must stay recoverable.

- `App` installs `Application.UnhandledException`, `TaskScheduler.UnobservedTaskException`, and `AppDomain.UnhandledException` in the constructor. Non-fatal UI faults set `e.Handled = true`, append to LocalFolder `error-log.txt` (beside `startup-error.txt`), and show `InfAppError` via `MainWindow.ShowError`. Unobserved tasks are observed and logged without spamming the InfoBar. Fatal corruption (`OutOfMemoryException`, `AccessViolationException`, `AppDomainUnloadedException`) is logged only and not swallowed.
- Startup failures still write `startup-error.txt`, also append via `ErrorReporter`, and call `ShowStartupFailure` instead of rethrowing (keeps the window alive with a paused spinner).
- Shared policy lives in `Helpers/ErrorReporter.cs` (no WinUI). `OperationCanceledException` / `TaskCanceledException` (and aggregates that are only those) are **not** errors — no log, no Notify. Wire `ErrorReporter.RunAsync` / `Run` around RelayCommand `Task` methods and `async void` handlers (Tags color/star, cloud-folder picker, Rooms `OnNavigatedFrom`, Settings source property saves, etc.). Prefer the page/VM `Notify` when one exists; otherwise the global presenter.
- `ErrorLog` is append-only, size-capped (~512 KB with one `.1` rotation). `ErrorThrottle` drops repeat unhandled keys inside a short window so a faulting layout pass cannot flood the log or InfoBar.
- `Palace.Tests` covers `ErrorReporter` / `ErrorLog` / `ErrorThrottle` (linked compile, off WinUI). Do not put WinRT types in those helpers.

## Library UI — do not freeze

Opening a project, Library, or a large folder must stay interactive.

- Call `Library.BeginBusy("Loading…")` **before** any await. `IsBusy` is ref-counted (`BeginBusy` / `EndBusy`).
- Progress: `PrgStartup` until the main shell is shown, then `PrgLibrary` on Library and `PrgProjectLoad` under the project combo. Bind Library bars to `IsBusy`. A freeze with no bar is a bug.
- Startup: activate the window **before** `InitializeAsync` / `LoadInitialDataAsync` (`App.OnLaunched` → `Window.Activate` → init → `ShowMain` → load). Do not await a full catalog load on a blank process.
- Status: `Loading…` → `Showing 80 of 2400` → the final count line.
- Project switch (`AppServices.SetCurrentProjectAsync`): bar first, Library, then Tags/Rooms/Settings. Tags mosaic is project-scoped.
- DB access: `PalaceDb.ReadAsync` / `WriteAsync` run the work on a thread-pool thread (`Task.Run`) while holding the single-connection gate, so `CatalogService` queries never execute on the UI thread. They take an optional `CancellationToken` (cancels the gate wait / a not-yet-started run, not work already inside SQLite). There is no sync `Read` / `Write` — never block on the gate. The `work` lambda runs off the UI thread: no `UiDispatch`, XAML, or `ObservableObject` mutation inside it, and no nested `ReadAsync` / `WriteAsync` (deadlock on the gate). Callers resume on their own context, so UI mutations after an await still go through `UiDispatch` when you are on a background thread.
- Folder browse: `GetAssetsAsync(folderPrefix:)` — do not load the whole project and filter in process. Top-level folder grouping runs on that prefix result (`FolderGroups`), not a whole-catalog in-process filter. Mosaic sort is the same query’s `ORDER BY` (`MosaicSortOrder.OrderBySql`); all-library and tag-browse mosaics also re-query instead of sorting `_allAssets` in process.
- Build `AssetItem`s off the UI thread. Chunk-append ~80 (`MosaicChunkSize`) on the dispatcher and `UiDispatch.YieldAsync`. Honor `_filterEpoch`.
- Mutate `Assets` only on the UI thread (`UiDispatch`). After chunks, `LinedFlowLayout.InvalidateItemsInfo` (`MosaicChunkAppended`).
- `ToItem` → `AssetItemMapper.FromAsset`. Never `File.Exists` or `ImageDimensions.TryRead` on the **original** while building the mosaic. Use stored Width/Height or a default aspect.
- Lazy thumbs: bind `ThumbImage`, not a static `FileToImage` during measure. Decode only realized tiles; cap in-flight decodes.
- `ItemsView` may not set `DataContext` on tiles and recycled containers do not re-fire `Loaded`. Stamp `Tag="{x:Bind MosaicTag, Mode=OneWay}"` on the `ItemContainer` (Id for tiles, `folder-group:` + path for headers) **and** `Tag="{x:Bind Id, Mode=OneWay}"` on the tile `Image`. Track live `Image`s and re-resolve via `GalleryMedia.FindAssetId` / `MatchesMosaicKey` on Tag / DataContext / chunk — do not untrack just because `DataContext` is not an `AssetItem`. Folder headers resolve through that mosaic key so tap / Open still navigates when Id and DataContext are empty.
- Overlay open is **double-click / Enter / Space / context Open** (Library and the Tags mosaic). **Esc** closes. **No single-click open.** Space opens the focused or selected tile (`GalleryScale.OpensOverlay` / `GalleryMedia.ShouldOpenOverlayFromSpace`); it does not toggle Select mode (click/tap still do). While overlay / GalleryWindow is open, do not mark Space handled on the viewer root (`GalleryScale.PassesViewerSpace`) — MediaPlayer play/pause and focused chrome use it; mosaic is a sibling so Space does not bubble there. Overlay close is **Esc** only. Do not synthesize a second click from `PointerPressed` on both the tile and `GrdAssets` — the same press arrives twice and opens on a single click. Do not open overlay from a header double-click or Space (`ShouldOpenOverlayFromDoubleTap` / `ShouldOpenOverlayFromSpace`): the first tap already navigates, and the second click can land on a new tile after the async mosaic reload. Overlay / GalleryWindow **backdrop** is in-app Acrylic (`GalleryOverlayBackdropBrush` in `App.xaml`) plus a light Smoke dim (`GrdGalleryBackdrop`) so the library blurs and darkens behind the still or video. Do not cover `MediaPlayer` transport; keep Info / Details. `GalleryWindow` uses `DesktopAcrylicBackdrop` (the blur of the library/desktop) plus **one** 0.28 Smoke layer — do not fill `GrdGalleryWindow` with Smoke and do not stack `GalleryOverlayBackdropBrush` on top (in-app acrylic only samples the window, so a full smoke fill hides desktop acrylic and double-dims).
- `LinedFlowLayout` aspect requests use `GalleryMedia.MosaicAspectCount` (requested range capped by remaining items) and `GalleryMedia.MosaicAspect` so folder headers take a full line (the caption stays compact in the template). Wire both `MosaicReset` and `MosaicChunkAppended` to `InvalidateItemsInfo`.
- `AssetItem.ContentHash` is required for lazy generate and viewport upgrade. Do not recover the hash from the JPEG file name.
- Overlay image/video sources are applied in code-behind (`UpdateOverlayMedia`). Do not rely only on nested `x:Bind` of `OverlayGallery.CurrentPath` through a converter — that path is null until `LoadCurrentAsync` finishes and often never refreshes.
- Overlay chrome: put title/tags in a **row below** the player (`BrdGalleryOverlayInfo` on Library). Toggle that bar with **Details** (`BtnGalleryDetails`, icon + text, Ctrl+I, `ShowDetails`; on by default) — do not cover `MediaPlayer` transport. Overlay **1:1 / Fit / Fill** stay in the top chrome with Info / Details (`BtnGalleryScaleActual` / `BtnGalleryScaleFit` / `BtnGalleryScaleFill`, icon + text, Ctrl+1/2/3) so packaged UI can find them when the overlay is open; do not hide those ids inside `BrdGalleryOverlayInfo` (Details off collapses that bar, and a plain Border has no UIA peer). Animated GIF stills keep autoplay via `GifFrames` delays + composite frames (`GifPlaying`); Pause keeps `GifFrameIndex` instead of restarting `BitmapImage`. `GalleryStillSurface` loads frames once with `TryRenderAll` and applies ticks from that cache — play `GifFrameIndex` ticks must not `RefreshAsync` / cancel that load while the cache is empty (`ShouldApplyGifTick` / `ShouldStartGifCompositeLoad`). The delay clock waits until composites exist (`ShouldRunGifPlayLoop` / `NotifyGifCompositeReady`) so Pause/slider during load keep frame 0. ## Cloud files — do not download the original

Two source kinds:

1. **Local + Files On-Demand** (OneDrive/Dropbox sync folders added with the normal folder picker).
2. **API sources** (`SourceKind.OneDrive` / `Dropbox`) after Settings → Connect. Connect opens the cloud-folder picker for the **current project**. Index via Graph / Dropbox `list_folder`. Store `CloudItemId` (`SourceFolder.CloudRootItemId`) + display path (`CloudSourcePath.Build`). Path stays UNIQUE across projects.

Detect On-Demand with `CloudFile.IsOnlineOnly` (`File.GetAttributes` only — not `File.Exists`, never a stream): `RecallOnDataAccess` (`0x00400000`) and `RecallOnOpen` mean hydrate-on-read. `FILE_ATTRIBUTE_PINNED` is local. **Dropbox** Files On-Demand placeholders are `SparseFile` + `ReparsePoint` and often omit Recall bits — those are online-only (`ScanContent.MayReadOriginal` is false). Hydrated OneDrive/Dropbox files keep `ReparsePoint` and may still show leftover `Offline` **without** Sparse — those are local and must be hashed/thumbnailed normally. Bare `Offline` (legacy HSM, or tests that stamp `FILE_ATTRIBUTE_OFFLINE`) is online-only. `CloudFile.IsCloudBacked` is the file badge signal (Recall / Pinned / Unpinned / Offline / Reparse / Sparse). `CloudFile.IsCloudBackedFolder` is the same signals on a **source root** (directories are not `IsCloudBacked`). Stamp tile `IsCloudBacked` with `GalleryMedia.StampIsCloudBacked` / `SourceFolderIsCloud` (API `SourceKind` or On-Demand root) plus the file flags — not only `IsOnlineOnly`. Use `CloudFile.Exists` / `TryGetAttributes` on user asset paths so placeholders are visible. `ImageDimensions.TryRead` refuses online-only paths. `HashService.HashFileAsync` is local files and explicit Open hydration only — never a cloud-vs-local probe, and never scan-on-placeholder.

On scan, if online-only:

- Do **not** `HashFileAsync`, metadata `Extract`, `BitmapDecoder`, or `ImageDimensions.TryRead` on the original.

- Set `Asset.IsOnlineOnly`. `FileInfo.Length` / last-write are safe.

Leave no JPEG — mosaic and preview show a kind **icon tile** (`ShowCloudTile` / `ShowPlaceholderTile`), not a blank image. Mosaic must **not** request thumbs for online-only (`ShouldRequestMosaicThumb` is false when `IsOnlineOnly`). `.avif` / `.heic` / `.heif` / `.psd` are catalog stills (`PathSafe.ImageExt`) but thumbs never `Open` the original: local video/AVIF/HEIC/PSD use `GetThumbnailAsync` only; if that fails, no JPEG. ## Cursor Cloud specific instructions

Cloud Agents run on **Linux**. On the Linux VM, only **`Palace.Tests`** (`net10.0`, off WinUI/WinRT) builds and runs. Keep those tests cross-platform. Windows-only remains `BuildAndRun.ps1` / `winapp` / `ui-tests.ps1` and live screenshots — not available on the Linux VM itself.

```bash
dotnet test ./Palace.Tests/Palace.Tests.csproj
```

**Self-hosted Windows worker.** For WinUI build/run, UI tests, screenshots, or visual design review of the live app, do **not** conclude "no Windows access" just because the Cloud Agent VM is Linux. Check connected workers with cursor-cloud `list-self-hosted-workers`. If a Windows worker is connected (e.g. `win-laptop` / My Machines), target it for that UI/visual work. If none is connected — or Developer Mode / the Palace checkout is missing — remind the user to set up or reconnect the Windows PC (Cursor CLI `agent worker start` from the Palace checkout, Developer Mode on, keep unlocked) before treating live UI verification as impossible.

The environment is repo-managed via `.cursor/environment.json`, whose `install` runs `.cursor/install.sh` to install the .NET 10 SDK into `$HOME/.dotnet` (added to `PATH`/`DOTNET_ROOT` in `~/.bashrc`) and warm a build of the test project.
