# Viewer swipe navigation: visual pager (APPROVED by Isiac Oct 22, 2026; KeepZoom amendment Oct 22)

Canonical copy for agents. Repo path: `docs/specs/swipe-nav.md`.

## Behavior
1. Drag: current image tracks finger 1:1; neighbor slides in from that side with a 16 px gap. Name and position (12 / 48) stay on current until commit.
2. Commit: release past 30% of viewer width, or flick > 0.5 px/ms in the drag direction. Both pages animate the rest of the way in 220 ms (range 200-250) with cubic-bezier(0.1, 0.9, 0.2, 1). Navigate and cross-fade the name/position chip at **animation start** (no flash-back to the old still). A flick back against the drag cancels even past 30%. A pinch mid-swipe cancels the pager and snaps back — do not classify stale drag on lift.
3. Snap back: below threshold with no flick, spring back to 0 in 280 ms (range 250-300), overshoot <= 4 px. Nothing else changes.
4. Edge resistance: on first/last item, offset = d * 0.3 / (1 + |d| / viewerWidth). Soft accent edge glow plus 'End of folder' / 'Start of folder' hint. Release always snaps back. No wrap-around.
5. Zoomed (browse only): Photos-style handoff. Drag pans until the image edge; extra travel in the same gesture pages, and the threshold counts only the handoff travel. When the still only overflows vertically (e.g. Fill on a portrait — no horizontal pan room), both edges are already pinned and paging starts immediately (no 24 px outward slop). **KeepZoomBetweenImages (#128):** on commit, reset local zoom/pan to Fit **only when that setting is off**; never write `GalleryViewModel.Scaling` from the pager. When KeepZoom is on, sticky scaling already carries Actual/Fill. Going back still restores a prior zoom/pan snapshot when one was saved. **Review mode:** no zoom-edge handoff — while zoomed, horizontal drag only pans; Keep/Reject/Skip need a fresh gesture at Fit (not zoomed).
6. Video: **visual pager deferred** — paging stays on the existing `VideoBrowseSwipe` path (#128). While playing, a horizontal drag on the real ProgressSlider (or the 28 px strip only when transport chrome is hidden) scrubs after slop; do not steal the #128 transport dead zone. Leaving a playing video should pause and save position (`onLeavePlaying`). Neighbor poster frames apply when the still pager later covers video.
7. Review mode is distinct: left/right = Reject/Keep with tilt + red/green tint card; the neighbor is NOT revealed during drag; after commit the next image arrives with the auto-advance slide (same 220 ms curve). Up = Skip. Review chip always visible. Outside Review, swipe never keeps or rejects.

## Timing
Drag 1:1; threshold 30% or 0.5 px/ms; commit 220 ms cubic-bezier(0.1,0.9,0.2,1); snap back 280 ms spring (<= 4 px overshoot); edge 0.3x with growing damping. If Windows Animation effects are off (UISettings.AnimationsEnabled == false), swaps are instant but the drag still tracks. Rapid input: an external StillRevision (arrows/buttons) stops settle animation without running its onDone; a new drag during settle interrupts and continues from the current offset.

## Implementation
- Custom pager, not FlipView (its ScrollViewer paging fights zoom/pan, the edge handoff, Review and the scrub bar, and gives no control over threshold or rubber-band).
- Hit-test: Manipulation stays on `GrdStillContent` (`ScrStill` ManipulationMode=None — putting Translate on the ScrollViewer made on-image swipes look like taps). Fit at 1× sizes that panel to the **viewport** (transparent) with the image / HDR letterboxed inside, so swipe-on-image, letterbox, and near-chrome all hit the same surface. Overlay toolbar **plates** are `IsHitTestVisible=False`; only real buttons / Details card / nav steal the gesture. Zoomed / Actual / Fill keep the panel equal to the image content (Fill portrait with no horizontal overflow pages immediately per §5).
- Three page visuals (prev/current/next) in a container. Translation driven by a Composition InteractionTracker (VisualInteractionSource on the viewer with redirection so the zoom ScrollPresenter/pan gets first claim), or manipulation-driven Translation, plus ExpressionAnimations for the neighbor offset and edge glow opacity, so it runs on the compositor thread at 120 Hz while the UI thread decodes.
- Commit/snap via tracker inertia modifiers (snap points at 0 / +-(width+16)) or a KeyFrame animation with the curve above. Reset transforms only after the new still is in place.
- Preload: decode +-1 neighbors at **screen size** from the cached **LargePreview** JPEG (`ExistingLargePreviewForPath` / `_lg`) when present — not the mosaic thumb (memory: one viewport-sized decode per neighbor, AutoPlay=false on GIF neighbors). HDR as FP16 when an item opens; after commit shift the ring and decode the new neighbor. Full resolution only on zoom. Peek skips folder headers and orphan/deleted rows. Neighbor preload may flash an SDR JPEG that then pops to HDR FP16 when that item becomes current — expected until the still pager can hold an FP16 neighbor surface.
- Composition owns `Translation.X` via a PropertySet; keep XAML `TranslateTransform.X` at 0 when that path is active (avoid 2× finger travel). Interrupt settle with `StopAnimation("X")` + a generation counter so stale `batch.Completed` is ignored. After browse commit, jump the new still to `releaseX ± stride` before settling to 0; hide neighbors before refresh so n+2 does not flash.
